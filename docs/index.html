Machine learning on AWS

Toronto next-day temperature forecast

A portfolio project: an XGBoost model trained on six years of Toronto weather, served through SageMaker, Lambda and API Gateway. Open this page and it asks the live model for a prediction.

Asking the model…

Fetching recent weather and running the model.

The model runs on a serverless endpoint that scales to zero when nobody is using it, so the first request after a quiet period takes about 10 seconds while it wakes up. Later requests take well under a second.

On days the model had never seen, its average miss was 2.0 °C (3.6 °F). Treat it as a guide, not a weather service.

    How it works

    1. Your browser calls GET /forecast on an API Gateway HTTP API (rate limited to protect costs).
    2. A Lambda function pulls the last nine days of hourly weather from Open-Meteo, turns complete days into 13 features (daily averages, 1- and 2-day lags, a 7-day average, month and day of year), and calls the model.
    3. A SageMaker serverless endpoint runs an XGBoost model trained on 2020–2025 data and returns the predicted average temperature for the next day.
    4. A daily job compares each saved prediction with what actually happened and publishes the error to CloudWatch, with alarms by email.

    Known limits

    • One city (Toronto), and the model only sees past observations. It does not use atmospheric simulations, so it is not a substitute for a real forecast.
    • The model was trained on Open-Meteo's historical archive, while this page feeds it the recent-data feed, so inputs can differ slightly from what it learned on.
    • The prediction is for the day after the latest complete day of data, which is normally today (UTC).
    • The first request after a quiet period is slow by design (serverless cold start).
    Built with AWS SageMaker, Lambda, API Gateway, Glue, Athena and CloudWatch. Weather data from Open-Meteo.
